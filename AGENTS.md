# Project rules

Read [docs/vision.md](docs/vision.md) and [docs/architecture.md](docs/architecture.md) before changing this project.

Before any visual change, also read the complete [canonical design language](docs/design-language.md), [current Rhapsody tokens](themes/rhapsody.toml) and [design-decision log](docs/design-decisions.md), and inspect the [original visual reference image](docs/references/braun-interface-concept.png). The [archived original specification](docs/references/original-design-reference.md) supplies source context. Evaluate Rhapsody work against the maintained design language and approved current state. The image and archive are historical evidence, not pixel targets; unapproved candidates and token values do not become decisions by existing in the repository.

Limux owns the product and Braun's functional precision; Rhapsody is its first theme. The current direction is contemporary and restrained: porcelain/cool-grey system surfaces, integrated graphite developer tools, precise hierarchy and purposeful state colour. The approved Quiet Workspace Strip has one inset orange active workspace (`#D46A43`) and plain inactive numbers. The original yellow boxed workspace concept remains a reference and recoverable baseline. Rofi's yellow selection edge and Foot's yellow cursor are current approved baselines whose future colours require separate review. Do not impose one accent across distinct states or reproduce historical decoration literally. Document proposed visual changes and approval status; obtain explicit authorization before live activation.

Limux owns functional behaviour; themes own appearance. Never change shortcuts, hardware support or input settings when applying a theme. Preserve working MangoWM, Mangobar, T2 audio, Touch Bar, backlight, Wi-Fi, trackpad and display/scaling settings. Inspect actual configuration before editing; validate replacements and rollback before removing anything. Maintain one canonical active configuration per component, avoid duplicate autostarts, orphan scripts, stale packages/configurations and unused dependencies, and preserve shared dependencies. Prefer Git history and documented recovery over redundant backup clutter; any necessary live replacement backup must have a defined rollback and cleanup lifecycle.

Keep generated outputs derived from shared theme tokens separate from human-maintained functionality. Scripts must be predictable, idempotent, validated and recoverable. Never commit secrets or personal data. Never push or create a remote without explicit approval. Do not claim a command exists until implemented and tested.
