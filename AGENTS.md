# Project rules

Read [docs/vision.md](docs/vision.md) and [docs/architecture.md](docs/architecture.md) before changing this project.

Before any visual change, also read the complete [canonical design language](docs/design-language.md), [current Rhapsody tokens](themes/rhapsody.toml) and [design-decision log](docs/design-decisions.md), and inspect the [original visual reference image](docs/references/braun-interface-concept.png). The [archived original specification](docs/references/original-design-reference.md) supplies source context. Evaluate every Rhapsody implementation against the complete design language and image, never a shortened aesthetic summary. The canonical design language is the maintained specification; the archive is historical evidence. Newer candidates and current token values do not automatically override established decisions.

Limux owns the product and Braun ET 66 design philosophy; Rhapsody is its first theme. Preserve the material hierarchy, subtle lavender-grey neutrals, purposeful signals (including the yellow active workspace), recessed inputs, subtle physical controls, historical influences and coordinated light system/dark developer tools. Document proposed changes and their approval status before modifying canonical values or state semantics. Typography, exact reconciled colour values, geometry and component treatments remain exploratory until explicitly approved and recorded. Do not silently promote implementation experiments into permanent design decisions. Obtain explicit authorization before live activation.

Limux owns functional behaviour; themes own appearance. Never change shortcuts, hardware support or input settings when applying a theme. Preserve working MangoWM, Mangobar, T2 audio, Touch Bar, backlight, Wi-Fi, trackpad and display/scaling settings. Inspect actual configuration before editing; validate replacements and rollback before removing anything. Maintain one canonical active configuration per component, avoid duplicate autostarts, orphan scripts, stale packages/configurations and unused dependencies, and preserve shared dependencies. Prefer Git history and documented recovery over redundant backup clutter; any necessary live replacement backup must have a defined rollback and cleanup lifecycle.

Keep generated outputs derived from shared theme tokens separate from human-maintained functionality. Scripts must be predictable, idempotent, validated and recoverable. Never commit secrets or personal data. Never push or create a remote without explicit approval. Do not claim a command exists until implemented and tested.
