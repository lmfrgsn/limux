# Project rules

Read [docs/vision.md](docs/vision.md) and [docs/architecture.md](docs/architecture.md) before changing this project.

Before any visual change, also read the complete [canonical design language](docs/design-language.md), [current Rhapsody tokens](themes/rhapsody.toml) and [design-decision log](docs/design-decisions.md). Evaluate Rhapsody work against the maintained design language and approved current state; unapproved candidates and token values do not become decisions by existing in the repository.

Limux owns the product and Braun's functional precision; Rhapsody is its first theme. The current direction is contemporary and restrained: porcelain/cool-grey system surfaces, integrated graphite developer tools, precise hierarchy and purposeful state colour. The approved Quiet Workspace Strip has one inset orange active workspace (`#D46A43`), white active text with a specific user-approved contrast exception, and plain inactive numbers. Foot's approved block cursor independently shares that orange swatch and uses dark `signal_ink` foreground. Foot uses Adwaita Mono 12.5 with 16px padding. The original yellow boxed workspace and yellow Foot cursor are historical states, recoverable from Git history. The application launcher and Command menu share one approved Limux picker design: a flat search with an orange caret above a hairline, and the bar's orange inset with white text as the selected row (the same narrow contrast exception). Thunar keeps graphite selection; its text fields are flat with an orange edge and caret while typing. The graphite picker selection, recessed search field and old yellow list edge are historical. Do not impose one accent across distinct states or reproduce historical decoration literally. Document proposed visual changes and approval status; obtain explicit authorization before live activation.

Limux owns functional behaviour; themes own appearance. Never change shortcuts, hardware support or input settings when applying a theme. Preserve working MangoWM, Mangobar, T2 audio, Touch Bar, backlight, Wi-Fi, trackpad and display/scaling settings. Inspect actual configuration before editing; validate replacements and rollback before removing anything. Maintain one canonical active configuration per component, avoid duplicate autostarts, orphan scripts, stale packages/configurations and unused dependencies, and preserve shared dependencies. Prefer Git history and documented recovery over redundant backup clutter; any necessary live replacement backup must have a defined rollback and cleanup lifecycle.

Keep generated outputs derived from shared theme tokens separate from human-maintained functionality. Live files remain canonical; `machine/` is their tracked copy, maintained with `scripts/machine.py capture` after a reviewed change. Never add private snippets or generated outputs to it. Scripts must be predictable, idempotent, validated and recoverable. Never commit secrets or personal data. Never push or create a remote without explicit approval. Do not claim a command exists until implemented and tested.
