This page describes current ownership and mechanics; historical preview instructions below do not describe the active design.

The activation controllers pin approved output hashes. Token or adapter edits alone do not change live files. This reconciliation keeps all generated appearance bytes identical to their pre-change versions. `scripts/theme.py render` still emits the historical boxed Mangobar CSS; the active bar is generated by `render_quiet()` through the Quiet Strip workflow. Both derive from the same token file, and the former remains available for recovery.

Each theme has one canonical semantic token file, such as themes/rhapsody.toml. A theme generator translates tokens into application-native formats. Generated appearance is separate from human-maintained functionality wherever supported; applying a theme must not change shortcuts or hardware. A future `limux theme apply rhapsody` is a design possibility, not an available command.

Targets include MangoWM borders, Mangobar, Rofi, Foot, Mako and GTK/Thunar. Each target needs a reviewed adapter, native-format validation, backup and rollback before live application. The generator emits Mangobar CSS, Rofi Rasi, a MangoWM appearance fragment, a Foot appearance fragment, the Thunar GTK 3 stylesheet, a Mako appearance fragment and a JSON token preview. Guarded component-specific activation mechanisms are available below; no generic live theme application command exists.

## Approved Mangobar activation and recovery

The user has approved candidate 2 as the initial baseline. `python3 scripts/activate-mangobar.py activate` performs session, startup, process ownership, launcher identity and known-style preflight checks, then atomically replaces only `~/.config/mangobar/style.css` and refreshes through the existing `~/.local/bin/limux-bar`. It requires an existing single managed bar, verifies exactly one afterward and leaves the existing single `exec_once` entry untouched. It refuses unknown styles or modified launchers rather than overwriting them.

Run from Foot in the desktop session:

```sh
cd ~/limux
python3 scripts/activate-mangobar.py check
python3 scripts/activate-mangobar.py activate
# Restore the pre-Rhapsody styling if needed:
python3 scripts/activate-mangobar.py rollback
```

The [recovery CSS](../themes/recovery/mangobar-before-rhapsody.css) is a historical version-controlled snapshot, guarded by the [manifest](../themes/recovery/mangobar.json). The manifest also pins the approved generated CSS: later token/adapter changes cannot silently become an authorized activation. Update that pin only after a new visual approval. Functional config and hardware are never copied into the repository or rewritten by this mechanism. No additional startup entry or service is installed. Failure during restart/verification restores the prior CSS and attempts a managed restart. Abrupt power loss/SIGKILL cannot run Python recovery, but atomic replacement prevents a partial CSS file; explicit rollback remains available from a healthy managed session. If the bar itself is absent, use the existing `~/.local/bin/limux-bar start` first, inspect its status/log, then retry rollback.

From Foot in the live session:

```sh
cd ~/limux
```

The refinement updates only generated candidate config/CSS and preserves the current launcher bytes; the pinned 0.2.2 binary, patches, MangoWM startup and hardware configuration remain untouched. The controller snapshots the previous active candidate in its existing private state while retaining the original pre-Strip rollback bytes. `restore-prior` reverts only the latest refinement; `rollback` still restores the original pre-Strip configuration and upstream binary. The user activated and visually confirmed this refinement from Foot. Live config and CSS hashes match the new candidate and the private manifest retains the prior candidate. The Codex process namespace cannot independently inspect the graphical bar process count.

## Rofi activation and rollback

The user approved commit `e1f7538` and authorized its permanent activation. No design values change in this workflow. From Foot in the desktop session:

```sh
cd ~/limux
python3 scripts/activate-rofi.py check
python3 scripts/activate-rofi.py activate
# Return to the previous working dark launcher:
python3 scripts/activate-rofi.py rollback
```

The tool reuses the token-driven adapter and pins its exact generated output in [rofi.json](../themes/recovery/rofi.json). It stages and parses the chosen theme, checks default config resolution and the existing Command+Space binding, compares complete functional configuration dumps, and requires a reachable Wayland session with no Rofi open before writing. Only `~/.config/rofi/charcoal.rasi` is replaced, atomically. Its historical filename is retained so `config.rasi` and all normal `rofi -show drun` shortcuts remain byte-identical. No wrapper, second active configuration, autostart entry or permanent backup is introduced. Temporary staging files are automatically removed; the operation lock lives in the runtime directory.

After replacement the tool validates the normal launcher with no theme override, verifies the selected theme and all protected hashes, and restores the immediately previous bytes if validation fails. Repeated activation/rollback is idempotent. A process/power failure cannot leave a partially written theme because replacement is atomic; explicit rollback remains available. Rofi reads the new theme on its next normal invocation, so no background service restart is needed.

The [original theme](../themes/recovery/rofi-before-rhapsody.rasi) and [original search icon](../themes/recovery/rofi-search.svg) are version-controlled historical recovery evidence, not additional live configs. The existing live icon is retained and checked for rollback integrity. The tool refuses unknown/modified live themes, functional configs or icons rather than overwriting them. Rollback does not depend on future adapter/token output matching the approved baseline.

Desktop functional validation after activation:

1. Press Command+Space. Confirm the approved Rhapsody launcher opens normally.
2. Type an installed application's name and confirm filtering; clear the search and use Up/Down (or Control+p/n) to move selection.
3. Press Escape and confirm dismissal without launching anything.
4. Reopen with Command+Space, search for a harmless application such as Thunar, select it and press Enter. Confirm it opens and Rofi closes.
5. If any check fails, close Rofi and run `rollback`, then repeat the checks with the prior theme.

The Codex environment cannot reach the live compositor, so interactive input/application-launch checks are pending on-device. Native parser/default-config checks and isolated activation/rollback tests pass; these do not claim to simulate keyboard input or application launching.

## MangoWM approved appearance and reversible preview

The `[mango]` section in [Rhapsody tokens](../themes/rhapsody.toml) drives `scripts/mango.py`. From Foot in the running MangoWM session:

```sh
cd ~/limux
python3 scripts/mango-appearance.py check
python3 scripts/mango-appearance.py preview --seconds 30
# Explicit recovery if a preview was interrupted:
python3 scripts/mango-appearance.py rollback
```

`check` validates both the original and merged full configuration with the installed parser, using temporary files removed immediately afterward. `preview` requires MangoWM 0.18.3, one existing compositor using the expected config, working IPC, and screenshot capture. It changes only owned values in the existing file, reloads that compositor, captures before/after images under `build/mango-candidate1/`, and restores after the timeout or Ctrl+C. It does not launch another compositor, bar or autostart entry. Native config reload reapplies the existing configuration; its unchanged `exec_once` entries are retained. Check window layout, focus, scaling and application controls during the preview as well as appearance.

An independent timed restorer is armed before any live replacement and exits after its bounded recovery window (preview duration plus 8 seconds). A single operation lock, pending visual-value journal and overwritten watchdog log live under `${XDG_STATE_HOME:-~/.local/state}/limux/mango-appearance/`. The pending journal is deleted after successful restoration; there are no accumulated full-config backups. After power loss or unavailable IPC, run `rollback` from Foot. Recovery restores disk values before attempting reload and keeps a failed operation journal for retry. Concurrent edits to nonvisual settings survive recovery; concurrent edits to owned visual values require review rather than being silently overwritten.

The [versioned recovery manifest](../themes/recovery/mango.json) records original values and the approved `fd645da` candidate hash. The user has approved that exact initial baseline; future adapter/token changes cannot silently inherit its approval. Activation uses native validation, atomic replacement, journalling and rollback in the existing single config. The transaction rejects any change outside the 16 owned values. Rollback is independent of future token changes. No general `limux theme apply` command is introduced.

Activate and validate from Foot:

```sh

python3 scripts/mango-appearance.py activate
python3 scripts/mango-appearance.py verify
# Restore the pre-Rhapsody appearance if necessary:
python3 scripts/mango-appearance.py rollback
```

`check` validates the configuration offline and reports whether its appearance is the approved baseline or the previous version. `verify` additionally requires the exact approved live values and one reachable compositor using that config; it does not claim pixel-level verification. Activation confirms exact post-reload config bytes and compositor IPC responsiveness before clearing the recovery journal. After success the timed restorer sees no pending operation and cannot undo the committed activation. Inspect the desktop to confirm the 2px borders, 8px inner / 12px outer gaps, 6px corners and approved colours. Shortcuts, layouts, gestures, animation and hardware settings are outside ownership and remain unchanged.

`scripts/foot.py`. `[foot.colors]` contains only additional muted ANSI hue roles;
`[foot.blends]` derives readable dark-surface variants from shared colours using
explicit sRGB channel mixes. Existing foundation and semantic signal values are

The fragment is **not** a replacement for the live configuration.

```sh
cd ~/limux

python3 scripts/preview-foot.py
# Alternatively, use your normal configured shell in the separate themed window:
python3 scripts/preview-foot.py --shell
# Optional actual desktop capture (includes other visible windows):
python3 scripts/preview-foot.py --capture
```

The preview reads `${XDG_CONFIG_HOME:-~/.config}/foot/foot.ini` and passes only
appearance settings through native `-o section.key=value` overrides. The fragment
and overrides come from the same adapter settings. It validates both the fragment
and the combination with the functional config using `foot --check-config` before
launch. There is no include added to the live file, no service, no second active
configuration, and no generated copy of functional settings. The resolved font
family is checked to prevent silent fallback. App ID, window rules, shell, TERM,
scrollback, clipboard bindings and mouse/keyboard behaviour are inherited. No
shell prompt or Codex settings are changed. Existing terminals remain running.

The specimen displays an explicitly fictional development transcript, all 16 ANSI
colours, secondary text and a selection-colour swatch. Its input prompt uses the
real cursor; drag to test actual selection. It never executes entered commands.
`wait` sleeps for ten seconds to test Ctrl+C, `ansi` redraws and `exit` closes.
`--shell` instead starts Foot's normal configured shell with its existing prompt.
Closing this separate window is the entire rollback; no file restoration is
needed. Ctrl+C in the invoking terminal cleans up only its preview child.
Generated artifacts and optional screenshot are under `build/foot-candidate1/`.
The palette is now approved at `5cf323e`; the guarded activation workflow below is separate from preview.

On-device review:

1. Compare alongside the light bar/launcher and approved window borders. Check
   text at the actual 2880×1800 / 1.5 output scale, including split windows.
2. Drag-select text; test Command+C/V and Ctrl+Shift+C/V at the specimen prompt.
   Check scrolling and selection across lines. The unchanged live configuration
   is used; native parser validation is not proof of interactive clipboard input.
3. Enter `wait`, press Ctrl+C and confirm interruption. Verify the orange cursor

Compatibility evidence comes from the installed `foot(1)` and `foot.ini(5)` for
1.28.0. In this version cursor colours belong in `[colors-dark]` as text/background
pairs. Foot renders flat terminal cells, not recessed inputs, inner borders or
material bevels; graphite field, aligned glyphs and 8 logical pixel padding supply

## Limux Files (Thunar) — activation and recovery

`[thunar]` tokens drive `scripts/gtk.py`, which generates three things: a GTK 3 stylesheet, a `Limux-Rhapsody` outline icon theme that inherits Adwaita, and nine Thunar view settings (toolbar items, path as buttons, Name/Size/Modified columns, outline sidebar icons at 16px, small toolbar icons, Today/custom dates, decimal sizes). The stylesheet's named colours apply to every GTK 3 app; its layout rules and the Inter font are scoped to Thunar windows. `themes/recovery/gtk.json` pins the approved output; token or adapter edits alone change nothing live.

From Foot in the desktop session:

```sh
sudo pacman -S adw-gtk-theme        # data-only GTK 3 theme, no dependencies
cd ~/limux
python3 scripts/activate-gtk.py check
python3 scripts/activate-gtk.py activate
python3 scripts/activate-gtk.py verify
# Restore default GTK theme, icons and Thunar view settings:
python3 scripts/activate-gtk.py rollback
```

Trash, removable-drive mounting and thumbnails come from the separately installed `gvfs` and `tumbler`, which start on demand over D-Bus; they are functionality, not part of this activation or its rollback.

With `gvfs` present, Thunar's file highlighting is on and it fills a selected grid item with GTK's `theme_selected_bg_color` (graphite) or `theme_unfocused_selected_bg_color` (metal), which the stylesheet defines; the label uses the same porcelain/graphite text as list selection. `css_previous_sha256` lets `activate` replace an earlier approved stylesheet in place and restore it if a later step fails.

Activation owns `~/.config/gtk-3.0/gtk.css`, `~/.local/share/icons/Limux-Rhapsody/`, the `font-name`, `gtk-theme` and `icon-theme` GSettings keys, and the nine Thunar properties. It refuses any existing value it does not recognise, writes the icons and stylesheet before switching the theme, and undoes completed steps if a later step fails. Running Thunar windows pick up the theme switch immediately but read the stylesheet and icon theme at start, so close all Thunar windows (or run `thunar -q`) and reopen. Firefox's default theme follows GTK, so restart Firefox and review its toolbars and file dialogs. The GTK interface font becomes Inter 10 system-wide (from Adwaita Sans 11). No shortcuts, Thunar accelerators or custom actions are changed.


Activation writes `~/.config/mako/rhapsody`, then removes appearance lines from the sole `~/.config/mako/config` and adds one `include=` at the end of its global section. Anchor, timeouts, visible count and the critical no-timeout rule stay in the user's file. Each config is validated first in a private Mako on its own D-Bus session; the live daemon is updated with `makoctl reload`, and any failure restores the prior bytes and reloads. Unknown configs or fragments are refused. The `mango-notifications` launcher and its single startup entry are unchanged.


## Limux picker — launcher and Command menu

The launcher and Command menu share one generated Rofi theme, `scripts/rofi.py` from `[rofi]` tokens, installed as the existing `~/.config/rofi/charcoal.rasi` by `scripts/activate-rofi.py`. Its only `configuration` keys are `drun-display-format` (the name, a tab, then the generic name as quiet secondary text) and `drun-match-fields` (`name,generic`, so Files and Terminal are still found as Thunar and Foot); the activation's functional-config comparison excludes exactly those two. Icons are left out by the theme; the functional `config.rasi` is unchanged. Secondary text uses Pango `fgalpha` so it stays legible on porcelain rows and the graphite selection.

The Command menu (`scripts/limux-commands.py`) sends markup rows: the action, a tab, and its key or verb. User text is escaped; Rofi matches the visible text, not the markup. Its override sets only the placeholder, row count and the quiet, nonselectable section labels, and it opens on the first command.

```sh
cd ~/limux
python3 scripts/activate-rofi.py check
python3 scripts/activate-rofi.py activate
python3 scripts/activate-rofi.py rollback          # previous yellow-edge Rhapsody launcher
python3 scripts/activate-rofi.py restore-original  # pre-Rhapsody launcher
python3 scripts/launcher-entries.py check
python3 scripts/launcher-entries.py activate
python3 scripts/launcher-entries.py rollback       # show all system entries again
```

`launcher-entries.py` writes per-user overrides in `~/.local/share/applications`: `Hidden=true` shadows for Foot Client, Foot Server, both Qt V4L2 tools, Rofi, Rofi Theme Selector, Bulk Rename, Thunar Preferences and About Xfce, and renamed copies of the Thunar and Foot entries (`Files`/`Thunar`, `Terminal`/`Foot`) that change only the main entry's names. `themes/recovery/launcher-entries.json` pins both the overrides and the system entries they copy, so a package update to those entries is reported for review rather than leaving a stale copy. Existing files are never overwritten; rollback removes only files still matching what it wrote.


## Thunar Command shortcuts

`scripts/thunar-shortcuts.py` gives Thunar's own actions Mac-style Command shortcuts in its accelerator map, `~/.config/Thunar/accels.scm`: ⌘C/X/V, ⌘Z and ⌘⇧Z, ⌘A, ⌘⌫ (move to Trash), ⌘D (duplicate), ⌘⇧N (new folder), ⌘↑/⌘↓ (parent/open), ⌘[ and ⌘] (back/forward), ⌘⇧H (home), ⌘L, ⌘F, ⌘T, ⌘W, ⌘Q, ⌘1–3 (views) and ⌘=/⌘−/⌘0 (zoom). Command keys MangoWM owns globally (N, I, R, O, M, G, E, K, Space, Tab, ←/→) are not used; those actions keep Thunar's defaults (for example Ctrl+N, Alt+Return, Ctrl+R).

Thunar rewrites this file itself, so the controller compares which shortcuts are set rather than bytes, refuses to write while Thunar is running, and refuses hand-edited maps. Rollback writes back Thunar's exact default dump from `themes/recovery/thunar-accels-default.scm`. The test suite compiles a small program against GTK 3 to confirm each key parses as a Command shortcut.

```sh
cd ~/limux
python3 scripts/thunar-shortcuts.py check
python3 scripts/thunar-shortcuts.py activate   # close Thunar first
python3 scripts/thunar-shortcuts.py rollback
```

## Bar status and agent indicators

`[bar_status]` tokens drive `scripts/bar_status.py`, which adds to the Quiet Strip config: Tabler level icons with values for Wi-Fi, battery and volume (`display` is `text`, `icon-value` or `icons`), the approved spacing (pair, item and group gaps; a right inset mirroring the left), and six modules per agent, one per colour or behaviour (quiet icon, spinning working icon, input icon, error icon, name, name in ink). The working icon's `spin-period` (from `spin_period`) makes the bar rotate it through `patches/mangobar/04-spin-custom-modules.patch`; Mangobar truncates module names past 31 characters, so slot names stay short. `patches/mangobar/05-icon-glyphs.patch` centres icon-font glyphs (Private Use Area) on the text's cap height and adds a top-level `glyph-scale` map; `wifi_icon_scale` and `battery_icon_scale` fill it, so only those short, wide glyphs are drawn larger. It also generates the fontconfig rule that makes Tabler the bar font's fallback; Mangobar draws every module with one font.

`scripts/agent-status.py` is functional: Claude Code and Codex call `agent-status.py hook <agent>` asynchronously for every relevant event. It records each session's state in `$XDG_RUNTIME_DIR/limux/agents` (never on disk), drops sessions whose agent process has exited, writes one text file per bar module (empty hides the module, through `patches/mangobar/03-hide-empty-custom-modules.patch`) and sends the bar its refresh signal. It signals only a bar whose config declares that signal, because an unhandled real-time signal would terminate it. Clicking an agent runs `agent-status.py focus <agent>`, which focuses the Foot window that owns the most urgent session. `agent-status.py status` lists live sessions.

From Foot in the desktop session:

```sh
cd ~/limux
python3 scripts/activate-bar-status.py check      # pins and live state, read-only
python3 scripts/activate-bar-status.py activate
python3 scripts/activate-bar-status.py verify
python3 scripts/activate-bar-status.py rollback   # exact previous Quiet Strip, no hooks
```

Activation layers over the active Quiet Workspace Strip. It requires the pinned Quiet Strip candidate, builds Mangobar with the three patches (reproducible; pinned hash), downloads Tabler 3.49.0 from npm and verifies its integrity and font checksum, installs `~/.local/share/fonts/limux/tabler-icons-3.49.0.ttf` and `~/.config/fontconfig/conf.d/60-limux-bar-icons.conf`, updates the Wi-Fi script from `machine/` (its default output is unchanged), replaces the patched binary, config and CSS, and merges asynchronous hooks into `~/.claude/settings.json` and a new `~/.codex/hooks.json`. Exact previous bytes are kept in `~/.local/state/limux/bar-status-activation`. While it is active, `activate-quiet-bar.py` refuses to act because the binary and config differ from its pins; roll back bar status first. Codex runs new hooks only after they are trusted once in its `/hooks` screen.
